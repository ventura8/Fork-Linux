# Fork for Linux (unofficial) v1.0.2 — System file dialogs that actually open

Fork for Linux (unofficial) runs the **official, unmodified** [Fork](https://git-fork.com) git
client for Windows under Wine. Fork is made by **Dan Pristupov and Tanya Pristupova**; this
project is **not affiliated with, endorsed by or supported by** them. Fork is paid software:
the evaluation is free, please [buy a license](https://git-fork.com/buy) if you keep using it.
Report wrapper problems at https://github.com/ventura8/Fork-Linux/issues, not to Fork support.

## What's fixed

- **System file dialogs work under Wine**: v1.0.1 registered `fl-filedlg.dll` under HKCU, but
  Wine's `FileOpenDialog` / `FileSaveDialog` live under HKLM (`comdlg32.dll`), so Open Repository,
  Clone, Save as Patch and folder picks still showed Wine's dialog. Setup now overwrites those
  HKLM InprocServer32 entries (`host_integration` rev 3); turning
  `[integration] system_file_dialogs` off restores `comdlg32.dll`.
- **Pickers reach zenity / kdialog through the hand-off daemon**: the launcher's `--handoff-only`
  daemon used to refuse `FL_REQ_HOST_HELPER` (EPERM), so even when our DLL ran, the Linux picker
  never started. Host-helper requests (including `pick-dir` / `pick-file` / `save-file`) are
  allowed on that daemon; plain git-bridge spawns stay refused.
- Folder start paths from Fork are converted with Wine's `wine_get_unix_file_name` before zenity
  sees them.
- E2E scenario **I-SYSTEM-FILE-DIALOGS**: with system file dialogs on, Init New Repository uses
  a stub zenity (not Wine's "Select repository" dialog) and creates the repository at the path
  it returns.

## Upgrade

After installing 1.0.2, the next `fork` / `fork-linux run` re-runs `host_shims` and
`host_integration` (rev 3). Fully quit Fork once so the new `fl-bridge-helper` is what the
launcher starts.
