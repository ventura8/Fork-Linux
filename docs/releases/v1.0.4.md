# Fork for Linux (unofficial) v1.0.4 — Every IDE in Open in

Fork for Linux (unofficial) runs the **official, unmodified** [Fork](https://git-fork.com) git
client for Windows under Wine. Fork is made by **Dan Pristupov and Tanya Pristupova**; this
project is **not affiliated with, endorsed by or supported by** them. Fork is paid software:
the evaluation is free, please [buy a license](https://git-fork.com/buy) if you keep using it.
Report wrapper problems at https://github.com/ventura8/Fork-Linux/issues, not to Fork support.

## What's new

- **Open in lists every IDE Fork supports that you have installed.** v1.0.3 put its Wine stubs
  where Fork never looks for most editors, so Fork 2.23.2 only showed VS Code, VS Code Insiders
  and Cursor. A `WINEDEBUG=+file` trace of Fork opening its Open in menu gave the exact paths it
  checks; the stubs now sit there, and Fork lists **VS Code, VS Code Insiders, Cursor, IntelliJ
  IDEA, PyCharm, WebStorm, PhpStorm, Rider, GoLand, Fleet, Sublime Text, Atom, Zed, Antigravity,
  Antigravity IDE and CodeBuddy**. GoLand, Fleet, Zed, Antigravity (both) and CodeBuddy are new.
- **Snap IDEs start again.** `/snap/bin/code` (and IntelliJ, Sublime Text, … as snaps) is a link
  to `/usr/bin/snap`, which picks the app from its own name; fork-linux resolved the link and so
  ran `snapd` instead of the IDE. The launcher is now kept as found.
- **Flatpak and JetBrains Toolbox IDEs are found**: besides `PATH`, fork-linux looks in Flatpak's
  exported launchers (user and system: `dev.zed.Zed`, `com.google.Antigravity`,
  `com.jetbrains.*`, …) and in `~/.local/share/JetBrains/Toolbox/scripts`.
- **Reveal-line calls** (`-g FILE:LINE`, `--line N`) reach the IDE instead of being refused.
- Like on Windows, Fork shows IntelliJ IDEA, PyCharm, PhpStorm and GoLand only for repositories
  with a `.idea` folder, and Rider only for .NET solutions (`*.sln`, `*.csproj`, …). Visual Studio
  has no Linux build; Android Studio is not in Fork's menu, so its stubs are removed.
- E2E **I-OPEN-IN-IDES** now opens Fork's real Open in menu, checks that all 16 IDEs are listed
  and clicks each one, checking that the matching Linux program gets the repository.
- **Also in this release (v1.0.3 was never published on its own): Stage All / file diffs when
  every script looked modified.** With `core.filemode=true`, Fork under Wine lists every executable
  file as changed with an empty diff. `fork-linux repo fix` (no path = every repository Fork knows)
  sets `core.filemode=false` and marks tracked symlinks `skip-worktree`; `repo undo` reverts that.
  Doctor's filemode hint points at `repo fix --yes`.
- Dependencies: ruff 0.17.1, Arch CI base `20261011.0.609700`. Fork 2.23.2, Kron4ek Wine 11.18
  staging (11.19 still breaks Fork), winetricks 20260125 and the GitHub Actions are already the
  latest.

## Upgrade

If Stage All still looks wrong in a repository, run `fork-linux repo fix --yes` (or
`fork-linux doctor --fix` and confirm).

The next `fork` / `fork-linux run` re-runs `host_integration`: stubs move to the paths Fork
checks, and the old ones are removed. Fully quit Fork once so the new `fl-launch.exe` is what the
stubs are copies of.
