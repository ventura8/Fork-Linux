# Fork for Linux (unofficial) v1.0.3 — Open in your IDEs, Stage All that works

Fork for Linux (unofficial) runs the **official, unmodified** [Fork](https://git-fork.com) git
client for Windows under Wine. Fork is made by **Dan Pristupov and Tanya Pristupova**; this
project is **not affiliated with, endorsed by or supported by** them. Fork is paid software:
the evaluation is free, please [buy a license](https://git-fork.com/buy) if you keep using it.
Report wrapper problems at https://github.com/ventura8/Fork-Linux/issues, not to Fork support.

## What's new

- **Open in lists your Linux IDEs**: VS Code, Cursor, IntelliJ IDEA, Sublime Text, Android Studio
  and other editors found on `PATH` appear in Fork's Open in menu. Setup copies `fl-launch.exe`
  to the Windows names Fork looks for (`Code.exe`, `Cursor.exe`, …) and starts the Linux program
  outside Wine's process tree (`fork-linux-host run`). `fork-linux doctor` reports which ones it
  sees. Install an IDE (or put it on `PATH`) and the next launch refreshes the list.
- **Stage All / file diffs when every script looked modified**: with `core.filemode=true`, Fork
  under Wine lists every executable file as changed with an empty diff, so Stage All and viewing
  a change look broken. `fork-linux repo fix` (no path = every repository Fork knows) sets
  `core.filemode=false` and marks tracked symlinks `skip-worktree`; `repo undo` reverts that.
  Doctor's filemode hint points at `repo fix --yes`.
- E2E **I-OPEN-IN-IDES** covers IDE stubs and `fork-linux-host run`; vital git change scenarios
  (stage / unstage / hunk / line / commit / amend) stay green.

## Upgrade

After installing 1.0.3, the next `fork` / `fork-linux run` re-runs `host_integration` (rev 4) so
Open in stubs are installed for IDEs on your `PATH`. Fully quit Fork once so the new
`fl-launch.exe` is what those stubs are copies of. If Stage All still looks wrong in a repository,
run `fork-linux repo fix --yes` (or `fork-linux doctor --fix` and confirm).
