# Fork for Linux (unofficial) v1.0.0 — First public release

Fork for Linux (unofficial) runs the **official, unmodified** [Fork](https://git-fork.com) git
client for Windows under Wine. Fork is made by **Dan Pristupov and Tanya Pristupova**; this
project is **not affiliated with, endorsed by or supported by** them. Fork is paid software:
the evaluation is free, please [buy a license](https://git-fork.com/buy) if you keep using it.
Report wrapper problems at https://github.com/ventura8/Fork-Linux/issues, not to Fork support.

## Highlights

- **`fork-linux` CLI and `fork` command**: `fork ~/src/repo` opens a repository; the first run
  sets everything up lazily and resumably (a pinned Kron4ek Wine 11.18 staging WoW64 runtime,
  .NET Framework via winetricks, the official Fork installer from `cdn.fork.dev`, all
  verified by size + sha256 before use).
- **Desktop integration**: menu entry, AppStream metainfo, our own neutral icon (Fork's icon is
  extracted from your own `Fork.exe` at runtime, at every icon size), "Open in Fork" for the
  installed file managers among Nautilus, Nemo, Caja, Dolphin, Thunar, PCManFM(-Qt) and FileManager-Actions
  (Thunar keeps your desktop's own custom actions), manual pages, bash / zsh / fish completions.
- **Follows your desktop**: Fork starts in the desktop's light or dark theme (or, when the desktop's
  theme cannot be read, with Fork's own "follow system theme" back on) and at its scale, and
  Open In Shell / Open In File Explorer reach the desktop's own terminal and file manager.
  Checked end to end in real desktop sessions of Ubuntu 26.04's flavours: Xubuntu (XFCE),
  Kubuntu (KDE Plasma on Wayland, its default session, and on X11), Ubuntu (GNOME Shell), Ubuntu
  Cinnamon, Ubuntu MATE, Ubuntu Budgie and Lubuntu (LXQt); see `docs/COMPATIBILITY.md`. On
  Cinnamon and MATE a menu entry in a new `~/.local/share/applications` shows after the next
  login, and fork-linux says so.
- **Readable interface text**: Fork's interface uses Selawik, Microsoft's open-source (SIL OFL
  1.1) stand-in for Segoe UI, downloaded pinned and sha256-verified; Windows' system fonts and
  ClearType gamma are set so Wine stops falling back to Tahoma.
- **Non-Latin text**: Cyrillic, Greek, Hebrew, Arabic, Indic, Thai, Hangul and Han text in Fork's
  interface falls back to the Linux fonts you have installed (Noto first), in the copy of WPF's
  composite font the installed .NET reads; the packages recommend the Noto fonts (core + CJK)
  where the format has weak dependencies, and `doctor` names them where it has none.
- **Terminals and apps outside Wine**: the terminal, file manager and default applications Fork
  opens are started outside Wine's process tree, so they never inherit Wine's restrictions: through
  your systemd user session, or without one through fork-linux's own launcher daemon;
  `doctor --check desktop.handoff` says which.
- **ssh keys and your ssh-agent**: `~/.ssh` keys, `known_hosts` and a translated config are shared
  with Fork's bundled ssh, and while Fork runs a relay lets it use your ssh-agent (`$SSH_AUTH_SOCK`),
  so a key you added with `ssh-add` is never asked for (`[ssh] agent_relay`, on by default; only
  listing and signing reach the agent; `doctor --check ssh.agent` says whether it works).
- **Fork updates and upgrades of fork-linux**: Fork's own updater keeps working under the wrapper
  (your Fork settings survive `update --fork` too); an upgrade of fork-linux re-runs only the setup
  steps that changed, and `doctor` says when a manifest override of yours keeps an old Wine or Fork
  pin. `fork-linux run --restart` ends a Fork that lost its window and starts it again.
- **Safety**: a snapshot of Fork's install before every launch, `rollback`, version pinning,
  `doctor` with `--fix` and `--json`, `logs --bundle`, a reversible `uninstall` (`--purge`
  deletes only what fork-linux created; `~/.wine` is never touched).
- **Experimental native-git bridge** (`git-bridge enable`): Fork's git calls run the host's
  git through small MinGW shims and a loopback daemon; off by default.

## Install channels (amd64 / x86_64 only)

| Channel | Artifact |
|---|---|
| Installer script (per user, `~/.local`) | `install.sh` + `fork-linux-1.0.0-x86_64.tar.gz` + `SHA256SUMS` |
| Debian / Ubuntu | `fork-linux_1.0.0_amd64.deb`; PPA `ppa:ventura8/fork-linux` (22.04, 24.04, 26.04) |
| Fedora 44 | `fork-linux-1.0.0-1.fc44.x86_64.rpm` |
| openSUSE Leap 16.0 | `fork-linux-1.0.0-1.lp160.x86_64.rpm` |
| AppImage | `fork-linux-1.0.0-x86_64.AppImage` (+ `.zsync`; uses the host Python >= 3.10) |
| Flatpak | `io.github.ventura8.ForkLinux-1.0.0-x86_64.flatpak` (org.winehq.Wine BaseApp stable-26.08, WoW64, freedesktop 26.08) |

Coming later: the AUR (`fork-linux`) and the Snap Store. Until then, on Arch Linux use the
installer script, the AppImage or the Flatpak.

No package depends on the distribution's `wine`, bundles Fork, or ships maintainer scripts:
all Wine state is created per user at first run.

## Known limitations

- "Show in Explorer" with a file selected opens the folder (Wine's explorer `/select`).
- Signing in to a GitHub account inside Fork can crash on Wine's WinRT notifications; use a
  personal access token instead.
- Wayland sessions use XWayland.
- Each new Wine prefix may use one of the license's 3 machine activations: deactivate your
  license in Fork before `fork-linux uninstall --purge`.
- The native-git bridge is experimental.
- With Fork's bundled git under Wine: hooks that start other programs are skipped, and an LFS push
  can hang (enable the git bridge for LFS repositories); now and then, mostly on busy repositories, Wine fails to
  start one of Fork's git calls and Fork shows a *Git Error* (`Win32Exception ... StartWithCreateProcess`): repeat
  the action, or enable the experimental git bridge (`fork-linux git-bridge enable`), which runs Fork's git calls
  with the Linux git outside Wine and avoids it. The README's "Known Wine limitations" has the details.
- Kron4ek Wine 11.19 and newer development builds do not run Fork yet; the pinned runtime is 11.18.
