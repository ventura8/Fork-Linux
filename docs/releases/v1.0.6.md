# Fork for Linux (unofficial) v1.0.6 — Open Git Bash works

Fork for Linux (unofficial) runs the **official, unmodified** [Fork](https://git-fork.com) git
client for Windows under Wine. Fork is made by **Dan Pristupov and Tanya Pristupova**; this
project is **not affiliated with, endorsed by or supported by** them. Fork is paid software:
the evaluation is free, please [buy a license](https://git-fork.com/buy) if you keep using it.
Report wrapper problems at https://github.com/ventura8/Fork-Linux/issues, not to Fork support.

## What's new

- **Open in > Open Git Bash opens your Linux terminal in the repository.** Fork starts its bundled
  Git for Windows bash there; under Wine that msys bash dies at the first subshell of Git's own
  start-up file, so nothing ever appeared. Fork's files stay untouched: while Fork uses its bundled
  git, fork-linux starts it with `POSIXLY_CORRECT` and `ENV` set, so an interactive bash reads only
  a small script of ours (`C:\fork-linux\git-bash.sh`) that hands the folder to the same terminal
  "Open In Shell" uses. Non-interactive shells (hooks, scripts) never read it, and no Linux program
  sees either variable. E2E **I-OPEN-GIT-BASH** clicks the menu item in the real Fork.
- The real-Fork E2E runner now rebuilds the Wine shims when its build is older than the sources
  (a second CI machine had been testing a stale build).

## Upgrade

Fully quit Fork once; the next launch writes `C:\fork-linux\git-bash.sh`.
