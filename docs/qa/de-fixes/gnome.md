# GNOME desktop tier: fixes needed in `src/fork_linux`

Found by the GNOME cell of the desktop E2E tier (`scripts/ci-e2e-de.sh gnome [--fork]`, Ubuntu
26.04: mutter 50 with Xwayland, gsd-xsettings 50, Nautilus 50.2 with python3-nautilus 4.1,
Ptyxis 50; see [../DE-E2E.md](../DE-E2E.md)). `src/` is not changed by the desktop tier's work:
the patch below is a proposal for whoever owns `src/fork_linux`. Until it is applied, the GNOME
integration tier fails exactly these tests (no `xfail`, no skip):

With the patch applied (checked on a scratch clone of this branch: the release tarball built from

unit tests below pass with 100 % line and branch coverage of `display.py` and
`desktop_integration.py` (Python 3.13 in `fork-linux-ci-coverage:26.04`, Python 3.10 in
`fork-linux-ci-jammy:22.04`); without it the 11 new or changed unit tests fail.

## 1. The Nautilus extension never loads on Nautilus 50 (Ubuntu 26.04)

`fork_linux_nautilus.py.in` asks for `gi.require_version("Nautilus", "4.0")`, then `"3.0"`.
Nautilus 50 ships only `Nautilus-4.1.typelib` and has already loaded API 4.1 when
nautilus-python imports extensions, so both calls raise `ValueError` ("Namespace Nautilus is
already loaded with version 4.1" / "not available for version 3.0"), the import fails and the
folder's context menu has no "Open in Fork". Fix: try 4.1, 4.0, 3.0 in turn and keep the first
that works; when none does (an API newer than we know is already loaded), import the namespace
as loaded. Nautilus 43-49 (4.0) and 3.x keep working. Evidence: with only fix 2 applied, the
tier's Nautilus logs `ValueError: Namespace Nautilus is already loaded with version 4.1` from
`fork_linux_nautilus.py` line 15 and the context menu never starts fork-linux (timeout waiting
for its license question).

## 2. A running Nautilus is not told to restart

Nautilus (like Thunar with `uca.xml`) loads extensions only when it starts. With a Files window
open while `install.sh` / `fork-linux desktop install` adds the extension (or `desktop remove`
takes it out), the change stays invisible and fork-linux says nothing, while Thunar gets
`THUNAR_RESTART`. Fix: `NAUTILUS_RESTART` ("run 'nautilus -q'"), emitted when the extension was
really written (not when it was already identical, not when a foreign file was left alone) or
removed, and only when a `nautilus` process runs (`procs.running`). The Thunar notice moves into
a shared `_tell_restart`.

## 3. GNOME's display scale with text scaling is read as the text scaling alone

`display.scale_percent` asks GNOME's gsettings (`scaling-factor` x `text-scaling-factor`) before
`Xft.dpi`. On GNOME's Wayland session (the only one since GNOME 49) Settings > Displays > Scale
lives in mutter's monitor configuration and `scaling-factor` stays 0 (automatic), so at 200 %
display scale with Large Text (1.25) fork-linux answers 125 % while gsd-xsettings publishes
`Xft.dpi` 240 (96 x 2 x 1.25) for X clients such as Wine: Fork comes out at half the size of
every other application. Fix: GNOME's own probe is `_from_xrdb` (`DESKTOP_PROBES["gnome"]`), so
`Xft.dpi` is asked right after the environment; the gsettings stay the fallback when there is no
`Xft.dpi`. Checked in the container: 100 % -> `Xft.dpi` 96, display 200 % -> 192, Large Text ->
120, both -> 240.
