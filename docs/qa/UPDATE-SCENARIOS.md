# Update scenarios: Fork updates and Fork for Linux upgrades

Every way the installed **Fork** can change version (its own Velopack updater, `fork-linux
update`, `rollback`, a pin) and every way **Fork for Linux (unofficial)** itself can be
upgraded, downgraded or reinstalled, with the expected result and the tests that prove it.
Each scenario has a stable ID (`F<n>` for Fork updates, `A<n>` for app upgrades) that tests,
commits and bug reports refer to.

The matrix is a checked contract: [`scripts/check-update-scenarios.py`](../../scripts/check-update-scenarios.py)
parses the two tables below and fails when an ID is missing or duplicated, a tier or status is
unknown, a test named under **Covered by** does not exist, a test named under **Planned**
already exists (move it to **Covered by**), or a row's status does not match its columns
(`tests/test_check_update_scenarios.py` runs it on this file). `--strict` additionally fails
while any scenario is not `covered`; that is the completion gate of the update-test work.

Background: [spike S9](../spikes/S9-fork-self-update.md) (Velopack under Wine: File > Check for
Updates... > Restart and Update; channel Stable lists 2.21.1, Develop offers 2.23.2; pinned ->
`ApplicationUpdateType = 2`; the bridge daemon's `--watch-prefix` survives Fork's self-restart;
rollback puts the version's full nupkg back), AGENTS.md "Update safety" and §4.9.

## Tiers

| Tier | What runs | Where |
|---|---|---|
| **U** | unit / integration tests with fakes (`xdg`, `fake_bin`, fake HTTP server, `fork_tree`, the fake bridge daemon); no Wine, no network | the host or any CI image (`pytest`) |
| **P** | packaging container E2E: build the package, install it, upgrade it from a real N-1 build (`scripts/build-version-variant.sh`), downgrade, remove, reinstall, as the unprivileged `tester` | `scripts/ci-packaging-cell.sh <format>` / `ci-packaging-matrix.sh` (Docker only) |
| **R** | real Fork + Wine E2E under Xvfb, driven by xdotool, screenshots kept in the scratch root | `scripts/e2e-docker.sh --name <label> pytest tests/e2e/...` (Docker only, AGENTS.md hard rule 18) |

Real-tier versions: **N-1 Fork = 2.23.1** (official `https://cdn.fork.dev/win/Fork-2.23.1.exe`,
installed with `setup --fork-version 2.23.1 --allow-untested`, trust on first use: Fork's
Develop feed lists `Fork-2.23.1-full.nupkg` with its SHA256), **N Fork = 2.23.2** (the pinned
default). App upgrades use **N-1 = 0.9.9**, built from this tree by
`scripts/build-version-variant.sh 0.9.9 OUTDIR FORMAT...`, and **N = `VERSION`**.

Status: **covered** = every tier listed has a test that exists; **partial** = some tests exist,
the rest are named under Planned; **planned** = nothing exists yet. Test references are
`path::test_name` (a leading `::name` repeats the previous file); for shell scripts
`path::function`.
